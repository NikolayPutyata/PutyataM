# ROADMAP: дизайн + SEO + реклама для weksar.com

## Логіка порядку (чому саме так)
- **Аналітика — першою.** Search Console і GA4 ставимо на поточний сайт одразу, щоб почали накопичуватись дані «до». Без них не виміряти ні SEO, ні рекламу.
- **Структура → дизайн → код.** Спершу визначаємо, які сторінки потрібні (за пошуковими запитами клієнтів), потім малюємо дизайн під ці сторінки, потім збираємо на Next.js.
- **Редизайн і міграцію на Next.js робимо одночасно.** Не перефарбовуємо старий React-сайт, щоб потім переписувати ще раз. Next.js віддає Google готовий HTML — для SEO це критично (звичайний React-сайт часто віддає пошуковику майже порожню сторінку).
- **Платну рекламу запускаємо на нові сторінки послуг**, а не на старий сайт: трафік на слабку сторінку = злитий бюджет.
- **SEO дає результат за 3–6+ місяців**, Google Ads — за дні після запуску. Тому вони паралельні, а не взаємозамінні.

## Фаза 1 — Аудит (Claude Code)
**Завдання:**
1. Визначити стек, збірку, хостинг, як деплоїться.
2. Перевірити рендеринг: що бачить пошуковик (сирий HTML сторінок без виконання JS — чи є там текст, заголовки, посилання).
3. Скласти повний список поточних URL (знадобиться для 301-редиректів).
4. По кожній сторінці: title, meta description, H1, структура заголовків, обсяг тексту, alt зображень.
5. Наявність robots.txt, sitemap.xml, canonical, Open Graph, мікророзмітки, `lang`.
6. Lighthouse (mobile): Performance, SEO, Accessibility; Core Web Vitals.
7. Форми: куди відправляються, чи є валідація, захист від спаму, згода на обробку персональних даних.
8. **Швидкий виграш:** поставити GTM + GA4 + верифікацію Search Console на ПОТОЧНИЙ сайт (ID — від Колі), щоб збирати дані вже зараз.

**Результат:** `docs/audit.md` — знахідки, список URL, пріоритети виправлень.

## Фаза 2 — Семантика і структура (Claude Code + Коля)
**Принцип:** один кластер пошукових запитів = одна сторінка. Людина, що шукає «прискорена ліквідація ТОВ», має потрапити на сторінку саме про це, а не на головну.

**Завдання:**
1. Зібрати пошукові запити. Джерела: Google Keyword Planner (Коля експортує CSV з Google Ads), підказки Google, сайти конкурентів, згодом — Search Console. Дослідження можна зробити в чаті з Claude з веб-пошуком.
2. Розділити запити за наміром:
   - **комерційні** («ліквідація ТОВ ціна», «замовити ліквідацію ТОВ Київ») → сторінки послуг
   - **інформаційні** («як ліквідувати ТОВ самостійно», «скільки триває ліквідація») → статті блогу з посиланнями на послуги
3. Кластеризувати і скласти карту сайту. Орієнтовна структура (послуги підтвердити з Колею, нічого не додавати «про запас»):
   - Головна
   - Сторінки послуг: ліквідація ТОВ; прискорена ліквідація / через зміну власника; ліквідація з боргами / банкрутство; ліквідація ФОП; реорганізація — **тільки ті, що реально надаються**
   - Ціни
   - Про нас / команда
   - Відгуки / кейси
   - FAQ
   - Контакти
   - Блог (статті під інформаційні запити)
   - Політика конфіденційності
4. URL-схема: латиниця, короткі, без дат (напр. `/likvidatsiia-tov`, `/blog/yak-likviduvaty-tov`).

**Результат:** `docs/seo-structure.md` — таблиця: URL · кластер запитів · намір · Title (до ~60 симв.) · Meta description (до ~155 симв.) · H1 · основні блоки сторінки.

## Фаза 3 — Дизайн (Claude Code + Коля)
**Напрям:** сучасно і помітно, але для юридичних послуг головне — **довіра**. Клієнт віддає тобі ліквідацію компанії, тому сайт має виглядати солідно й чітко, а не «кричати». Помітність — через сильний перший екран, контраст, типографіку і чисту структуру, а не через миготіння й важкі анімації.

**Завдання:**
1. Проаналізувати референси з Фази 0, запропонувати 2–3 візуальні напрями (кольори, шрифти, настрій) — Коля обирає один.
2. Дизайн-система (design tokens): палітра (основний, акцентний для CTA, нейтральні), шрифти з повною підтримкою кирилиці й української (напр. Manrope, Onest, Inter, Unbounded для заголовків), шкала розмірів, сітка, відступи, радіуси, тіні.
3. Ключові компоненти:
   - Перший екран: чітка пропозиція («що · для кого · за скільки/за який строк») + головна кнопка дії
   - «Як це працює» — кроки
   - Ціни / пакети
   - Чому ми (конкретні факти, не загальні фрази)
   - Відгуки / кейси
   - FAQ-акордеон
   - Форма заявки (мінімум полів) + кнопки месенджерів
   - На мобільному — закріплена кнопка дзвінка/месенджера
4. Mobile-first: більшість трафіку з телефонів.
5. Спочатку прототип **головної + однієї сторінки послуги** → погодження Колею → решта сторінок.
6. Обмеження: контраст тексту за WCAG AA; шрифти через `next/font`; зображення через `next/image` (WebP/AVIF); анімації — легкі, з повагою до `prefers-reduced-motion`.

**Результат:** `docs/design-system.md` + компоненти в коді + погоджений прототип.

## Фаза 4 — Розробка на Next.js з вбудованим SEO (Claude Code)
**Технічний SEO-чекліст (кожен пункт обов'язковий):**
- [ ] Усі публічні сторінки — статична генерація (SSG) або SSR; текст є в HTML без JS
- [ ] Унікальні `title` і `description` для кожної сторінки (Metadata API) — з `docs/seo-structure.md`
- [ ] `canonical` на кожній сторінці
- [ ] `sitemap.xml` (генерується автоматично, `app/sitemap.ts`) і `robots.txt` (`app/robots.ts`)
- [ ] `<html lang="uk">`
- [ ] Один H1 на сторінку, логічна ієрархія H2/H3, семантичні теги
- [ ] Open Graph + зображення для поширення в месенджерах
- [ ] Мікророзмітка JSON-LD: `Organization` / `LegalService` (LocalBusiness), `Service` на сторінках послуг, `BreadcrumbList`, `FAQPage` (розширені FAQ-сніпети Google зараз майже не показує для комерційних сайтів, але розмітка не шкодить), `Article` для блогу
- [ ] Хлібні крихти на внутрішніх сторінках
- [ ] Внутрішня перелінковка: статті → послуги, послуги ↔ суміжні послуги
- [ ] `alt` у всіх змістовних зображень
- [ ] Коректна сторінка 404
- [ ] Core Web Vitals (mobile): LCP < 2,5 с, INP < 200 мс, CLS < 0,1

**Аналітика і конверсії:**
- [ ] GTM + GA4 через змінні середовища
- [ ] Події в `dataLayer`: `generate_lead` (відправка форми), `click_phone`, `click_messenger`, `click_email`
- [ ] UTM-мітки зберігаються і передаються разом із заявкою (щоб бачити, звідки клієнт)

**Форми і персональні дані:**
- [ ] Валідація, захист від спаму (honeypot / Cloudflare Turnstile)
- [ ] Відправка в обраний канал (Telegram-бот / email / CRM)
- [ ] Чекбокс згоди на обробку персональних даних + посилання на Політику конфіденційності (Закон України «Про захист персональних даних»)
- [ ] Сторінка Політики конфіденційності: хто володілець даних, які дані, мета, строки, права суб'єкта, використання аналітики/cookies. Текст на юридичну перевірку Колі

**Результат:** робочий сайт на staging-домені.

## Фаза 6 — Реклама (Коля + Claude)
### 6.1 Google Ads — пошукова реклама (старт)
**Готує Claude Code** (`docs/ads/google-ads-plan.md`):
- Структура кампанії: 1 кампанія «Пошук», групи оголошень = сторінки послуг
- Ключові слова (фразова й точна відповідність, комерційні запити з Фази 2)
- Мінус-слова: безкоштовно, самостійно, зразок, шаблон, бланк, вакансія, робота, курсова, реферат, закон, стаття ЦКУ, онлайн-тест тощо
- 2–3 адаптивні оголошення на групу (заголовки + описи)
- Розширення: дзвінок, уточнення, посилання на сайт, адреса
- UTM-шаблон
- Налаштування конверсій (імпорт `generate_lead` з GA4 або тег Google Ads через GTM)

**Робить Коля** (або Claude у браузері з підтвердженням Колі):
- Створити акаунт Google Ads, пройти верифікацію рекламодавця, додати оплату
- Створити кампанію за планом; на старті вимкнути «Пошукових партнерів» і «Контекстно-медійну мережу»
- Тестовий період 2–4 тижні з невеликим денним бюджетом (суму визначаємо після оцінки ставок у Keyword Planner)

**Головна метрика:** ціна однієї заявки (CPL) порівняно з тим, скільки приносить один клієнт.

### 6.2 Meta — ретаргетинг (після запуску сайту і появи трафіку)
- Claude Code: Meta Pixel + Conversions API (серверні події через route handler Next.js), ті самі події, що й у GA4
- Аудиторія: відвідувачі сторінок послуг за 30 днів, які не залишили заявку
- Холодний таргет (людям, які не були на сайті) — тільки як окремий тест пізніше; для юридичних послуг зазвичай дорогий і слабкий

### ⚠️ Юридичні та модераційні ризики реклами
- Закон України «Про рекламу»: реклама має бути достовірною; заборонена недобросовісна реклама. **Не обіцяти гарантованого результату**, не писати «без перевірок», «100% без ризиків», «закриємо будь-які борги»
- Порівняння з конкурентами — тільки з фактами, що можна підтвердити
- Google і Meta суворіше модерують фінансові та юридичні послуги; агресивні формулювання → відхилення оголошень або блокування акаунта
- Ціни в рекламі мають збігатися з цінами на сайті

## Фаза 7 — Постійне SEO (щомісяця)
- **Контент:** 2–4 статті на місяць під інформаційні запити з Фази 2 (напр. як ліквідувати ТОВ, строки, документи, вартість, ліквідація з боргами, ліквідація vs зміна власника). Кожна стаття — з посиланням на відповідну послугу. Юридичну точність перевіряє Коля
- **Довіра й посилання:** відгуки в Google Business Profile (просити кожного задоволеного клієнта), профілі в бізнес-каталогах і довідниках, згадки на профільних ресурсах. Без купівлі масових посилань — Google за це карає
- **Оновлення:** раз на квартал переглядати сторінки послуг (ціни, строки, зміни законодавства)
- **Звіт** (`docs/reports/YYYY-MM.md`): Search Console (покази, кліки, середня позиція за ключовими запитами), GA4 (заявки за джерелами), Google Ads (CPL), висновки і план на місяць. Дані експортує Коля, звіт пише Claude Code
