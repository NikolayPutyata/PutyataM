# Як залити сайт на хостинг (фрихост) — вручну

На `weksar.com` заливається **новий сайт** (папка `web/`, Next.js). Він збирається в готові HTML-файли, які ти перезаливаєш на хостинг сам. Автозаливки немає (рішення Колі, 22.11.2026).

Старий сайт (корінь репозиторію, Vite) лишається в репозиторії для відкату.

> **Увага:** `npm run build` у **корені** репозиторію збирає **старий** сайт (папка `dist/`). Новий збирається тільки з папки `web/` (див. нижче), результат — `web/out/`. Як відрізнити: у старому сайті на хостингу є папка `assets/` з файлами `index-….js`, у новому — папка `_next/` і файли на кшталт `likvidatsiia-tov.html`.
>
> Найпростіший шлях: Claude після кожної зміни дає готовий архів `weksar-site.zip`. Його досить розпакувати в корінь сайту на хостингу (крок 2) і нічого не збирати.

## 1. Зібрати (на своєму комп'ютері)

Потрібен Node.js — той самий, яким збирався старий сайт. У папці проєкту:

```bash
git checkout main
```
```bash
git pull
```
```bash
cd web
```
```bash
npm install
```
```bash
npm run build
```

Після збірки з'явиться папка `web/out/` — це і є весь сайт. Під час збірки в консолі буде рядок `.htaccess: 29 постійних (301) …` — так і має бути.

**Google Tag Manager:** коли з'явиться ID, створи у `web/` файл `.env.local` з рядком `NEXT_PUBLIC_GTM_ID=GTM-XXXXXXX` і збери заново.

## 2. Залити

Найпростіше — архівом:
1. Відкрий `web/out/`, виділи **весь вміст** (Ctrl+A) → правою кнопкою «Стиснути в ZIP».
   - У виділенні має бути файл `.htaccess`. Якщо його не видно: Провідник → «Вигляд» → «Показати» → «Приховані елементи».
2. У файловому менеджері фрихосту відкрий кореневу папку сайту → завантаж ZIP → «Розпакувати» з заміною файлів.
3. Видали ZIP з хостингу.

Старі файли старого сайту (папка `assets/`, картинки) можна видалити, а можна лишити — вони нікому не заважають.

**Перед першою заливкою** збережи копію нинішнього `.htaccess` з кореня сайту, якщо він там є.

## 3. `weksar.com.ua`

У панелі фрихосту прив'яжи `weksar.com.ua` і `www.weksar.com.ua` до того самого сайту як синонім (alias). Переадресацію на `weksar.com` зробить `.htaccess`.

## 4. Перевірити після заливки

| Відкрий | Має бути |
|---|---|
| `https://weksar.com` | новий сайт (темний перший екран) |
| `https://weksar.com/services/liquidation` | перекидає на `https://weksar.com/likvidatsiia-tov` |
| `https://weksar.com/qwerty` | сторінка «Сторінку не знайдено» |
| `https://www.weksar.com` | перекидає на `https://weksar.com` |
| `https://weksar.com/robots.txt` | `Allow: /` і посилання на sitemap |
| `https://weksar.com/sitemap.xml` | список з 50 сторінок |
| `http://weksar.com` | перекидає на `https://`. Якщо ні, увімкни в панелі фрихосту перенаправлення на HTTPS |

**Тестова заявка:** форма на будь-якій сторінці. Поки сервер заявок вимкнений, форма запропонує надіслати заявку у WhatsApp — так і має бути.

## Відкат на старий сайт

1. Видали з хостингу `.htaccess`, `index.html` і папку `_next`.
2. Збери старий сайт: у корені репозиторію `npm install`, потім `npm run build`.
3. Залий вміст `dist/`.

## Тестова копія (необов'язково)

Щоб зібрати копію, закриту від Google (наприклад, для піддомену), збирай так:

```bash
NEXT_PUBLIC_SITE_ENV=staging npm run build
```
