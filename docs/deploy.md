# Як новий сайт потрапляє на хостинг (фрихост)

З 22.11.2026 на `weksar.com` заливається **новий сайт** (папка `web/`, Next.js, готові HTML-сторінки). Старий сайт (корінь репозиторію, Vite) лишається в репозиторії для відкату.

## Як це працює

Кожне оновлення гілки `main` запускає на GitHub автозаливку (`.github/workflows/deploy.yml`):
1. збирається новий сайт (`web/`) у режимі продакшн: індексація дозволена, sitemap і robots для Google;
2. генерується `.htaccess`:
   - 301-переадресації зі старих адрес (`/services/...`) на нові;
   - якщо нова сторінка ще не готова — тимчасовий 302 на головну;
   - `www` і `weksar.com.ua` → `weksar.com`;
   - справжня сторінка 404;
3. усе заливається по FTP у папку сайту.

## Налаштувати один раз (робить Коля)

Паролі зберігаються в GitHub зашифрованими. Їх не бачу ні я, ні код.

1. У панелі фрихосту знайди **FTP-доступ**: адресу сервера (напр. `ftp.weksar.com` або `sXX.freehost.com.ua`), логін, пароль. Подивись також, як називається **папка сайту** при підключенні по FTP (напр. `/weksar.com/www/`).
2. GitHub → репозиторій `PutyataM` → **Settings** → **Secrets and variables** → **Actions**.
3. Вкладка **Secrets** → «New repository secret»:
   - `FTP_SERVER` — адреса FTP-сервера;
   - `FTP_USERNAME` — логін;
   - `FTP_PASSWORD` — пароль.
4. Вкладка **Variables** → «New repository variable»:
   - `FTP_SERVER_DIR` — папка сайту з `/` в кінці, напр. `/weksar.com/www/`;
   - `GTM_ID` — ID Google Tag Manager `GTM-XXXXXXX`, коли з'явиться (необов'язково);
   - `FTP_PROTOCOL` = `ftp` — лише якщо заливка падає з помилкою TLS.
5. Вкладка **Actions** → «Деплой на хостинг» → **Run workflow**. Через 2–3 хвилини сайт оновиться. Далі все відбувається само після кожного мерджу в `main`.

**Перед першою заливкою:** якщо в корені сайту на хостингу вже є `.htaccess`, збережи його копію: автозаливка замінить його новим.

## `weksar.com.ua`

У панелі фрихосту прив'яжи `weksar.com.ua` і `www.weksar.com.ua` до того самого сайту як синонім (alias). Переадресацію на `weksar.com` зробить `.htaccess`.

## Перевірити після заливки

| Відкрий | Має бути |
|---|---|
| `https://weksar.com` | новий сайт (темний перший екран) |
| `https://weksar.com/services/liquidation` | перекидає на `https://weksar.com/likvidatsiia-tov` |
| `https://weksar.com/qwerty` | сторінка «Сторінку не знайдено» |
| `https://www.weksar.com` | перекидає на `https://weksar.com` |
| `https://weksar.com/robots.txt` | `Allow: /` і посилання на sitemap |
| `https://weksar.com/sitemap.xml` | список сторінок |
| `http://weksar.com` | перекидає на `https://`. Якщо ні, увімкни в панелі фрихосту перенаправлення на HTTPS |

**Тестова заявка:** форма на будь-якій сторінці. Якщо сервер заявок вимкнений, форма запропонує надіслати заявку у WhatsApp — так і має бути.

## Відкат на старий сайт

Якщо щось пішло не так:
1. Видали `.htaccess` з кореня сайту через файловий менеджер. Сайт продовжить працювати, але без переадресацій.
2. Або напиши мені. Я поверну в `.github/workflows/deploy.yml` збірку старого сайту (корінь репозиторію, `npm run build`, папка `dist/`).
